1. Abstract & Design Goals

Kora is a user-modelling system that, given a known shopper U and a product description P, generates a free-form review and a 1–5 star rating that mimic U's historical voice, rating calibration, and cultural register (with a Nigerian-locale specialisation). The system combines (i) an offline persona-construction pipeline that ingests multi-source review corpora, (ii) a Neo4j knowledge graph with a 384-dim vector index over review text, (iii) a SQLite persona store of stylometric and rating-bias statistics for 25k users, and (iv) an online inference path that performs schema-aware Cypher retrieval and a two-call Gemini in-context-learning generation, streamed to the client via WebSocket.

Goals: (1) persona fidelity — the output must read like the specific user, not a generic reviewer; (2) locale grounding — Nigerian shoppers' Pidgin/price/authenticity register is preserved; (3) retrieval transparency — every generation is traceable to the graph subgraph that produced it; (4) low-latency streaming — first token under one second on warm models.

4.1 Source ingestion (pipeline/sources.py)

  • Amazon — global multi-category reviews, used as the base US-locale corpus.
  • Nigerian e-commerce — Jumia/Konga combined product reviews keyed on combined_root, joined with load_combined_meta for item metadata.
  • Google Maps — Nigerian-place reviews, joined with load_nigerian_places to ground locale.

4.2 Persona-friendly sampling (pipeline/sampler.py)

Naive uniform sampling collapses persona signal because most users contribute only a single review. persona_friendly_sample stratifies by user_id, preferring users with ≥ MIN_WORDS_FOR_STYLOMETRY-word reviews and ≥ 2 historical reviews so the persona store contains learnable users instead of singletons.

4.3 Enrichment (pipeline/enrichment.py)

Two enrichments per record:

Stylometry (per review, then aggregated per user)

compute_stylometry(text) → {
  avg_sent_len, vocab_richness, exclamation_rate,
  caps_rate, pidgin_freq, emoji_rate, question_rate,
  avg_word_len, uppercase_word_rate,
  naira_mention (bool), price_sensitivity (bool),
  authenticity_concern (bool)
}

pidgin_freq is the share of tokens in a curated PIDGIN_TOKENS lexicon (e.g. "abeg", "wahala", "sef", "shey"); naira_mention/price_sensitivity/authenticity_concern are boolean flags from substring rules — these provide the cultural-voice signal exploited at inference time. Reviews shorter than MIN_WORDS_FOR_STYLOMETRY get an empty dict, deliberately excluding them from the per-user aggregate.

Embeddings

SentenceTransformerEmbedder("all-MiniLM-L6-v2") in CPU batches of EMBED_BATCH (default 64) produces 384-dim vectors written to Review.embedding. A HashingEmbedder fallback (SHA-1 → bucketed token counts, L2-normalised) is used in deterministic test runs to skip the model download.

4.4 Per-user aggregation (pipeline/user_accumulator.py)

UserAccumulator ingests every enriched record, then flushes to SQLite as two tables:

  • personas — one row per user_id with locale, platform, review_count, rating_mean, rating_std, rating_skew, top_categories (JSON), and the mean of every stylometry metric.
  • category_rating_bias — (user_id, category) → (mean, count); lets inference predict ratings within the target category instead of the user's global mean.

An is_persona_eligible flag marks users with enough reviews/words to drive ICL.

4.5 Neo4j write (pipeline/neo4j_writer.py)

Idempotent MERGE writes (so reruns are safe), batched at NEO4J_WRITE_BATCH:

MERGE (u:User {id: row.user_id}) ON CREATE SET u.locale = …, u.platform = …
MERGE (i:Item {id: row.item_id}) ON CREATE SET i.title = …, i.brand = …, i.category = …, i.price = …
MERGE (cat:Category {name: row.category})
MERGE (plt:Platform {name: row.platform})
MERGE (r:Review  {id: row.review_id}) ON CREATE SET r.text = …, r.rating = …, r.embedding = …, …
MERGE (u)-[:WROTE {timestamp: row.timestamp}]->(r)
MERGE (r)-[:ABOUT]->(i)
MERGE (i)-[:IN_CATEGORY]->(cat)
MERGE (i)-[:SOLD_ON]->(plt)

Indexes are created at the end of the write:

CREATE INDEX user_id        FOR (u:User)   ON (u.id)
CREATE INDEX item_id        FOR (i:Item)   ON (i.id)
CREATE INDEX review_id      FOR (r:Review) ON (r.id)
CREATE INDEX review_locale  FOR (r:Review) ON (r.locale)
CREATE INDEX item_category  FOR (i:Item)   ON (i.category)
CREATE VECTOR INDEX review_embedding
  FOR (r:Review) ON (r.embedding)
  OPTIONS { indexConfig: {
    `vector.dimensions`: 384, `vector.similarity_function`: 'cosine'
  } }

7. Retrieval Subsystem

Three branches are selectable at runtime (branch ∈ {ppr, query, vector}) and the choice is recorded on every graph_data event and the final payload, giving an auditable retrieval-provenance label for every generation.

BranchTriggerCypher used for content anchors
ppritem_id resolves in QUERY_ITEM_METAQUERY_B: locale-weighted scoring on other users' reviews of the exact item.
queryNo item_id but raw_message presentLLM-generated Cypher (Call 1) executed against the schema; falls through to QUERY_B or QUERY_VECTOR on empty/error.
vectorNo item_id and no raw_messageQUERY_VECTOR: db.index.vector.queryNodes('review_embedding', 15, $item_vec) with cosine > 0.72 and locale re-ranking.

7.1 Style anchors — user's own reviews (always)

QUERY_A_SAME_CAT  — user's K=3 most-recent reviews in the same category as target
QUERY_A_ANY_CAT   — backfills if same-category yields < K
QUERY_OWN_RECENT  — used when item_id is unknown (no category to filter on)

Selecting style anchors from the same category first is what lets the model imitate domain-specific vocabulary (a "fashion" review reads nothing like an "electronics" review even from the same user).

7.2 Content anchors — other users' reviews (locale-weighted)

QUERY_B (PPR-style, executed when item_id is known):
  MATCH (target:Item {id:$item_id})<-[:ABOUT]-(r:Review)<-[:WROTE]-(other:User)
  WHERE other.id <> $user_id
  WITH r, other,
       CASE WHEN other.locale = u.locale THEN 1.0 ELSE 0.3 END AS locale_w,
       duration.between(datetime({epochSeconds:r.timestamp}), datetime()).months AS age
  WITH r, (locale_w * 0.6 + (1/(1 + age/12.0)) * 0.4) AS score
  ORDER BY score DESC LIMIT $N

The score combines a locale prior (0.6 weight) with a recency decay (0.4, halving roughly every 12 months). Same-locale recent reviews dominate, but the 0.3 floor for cross-locale lets US reviews still contribute when the NG corpus is thin.

7.3 LLM Cypher generation (branch query)

inference/retrieval.py :: generate_retrieval_query injects the full schema (node labels, properties, relationships, vector index name, three example query patterns) into a prompt and asks Gemini for a single RetrievalQuery {cypher: string} JSON object via response_mime_type: "application/json" + Pydantic response_schema. The string is validated to start with MATCH or CALL (read-only guard) and executed with $user_locale and $item_vec bound. On empty rows or exceptions the call falls through to QUERY_B → QUERY_VECTOR.

Read-only guard

The instruction prompt forbids CREATE / DELETE / SET / MERGE; the post-validation also accepts only MATCH/CALL starts. There is no Cypher parser in the loop, but the structured-output contract eliminates markdown fences and natural-language prose that would otherwise need regex-stripping.

7.4 Vector fallback

$item_vec is computed at request time by encoding user_query = raw_message + item_name + item_description + item_id through the same all-MiniLM-L6-v2 used in the pipeline (cached globally on first call). The 0.72 cosine threshold was chosen empirically — below it, retrieved reviews are off-topic; above it, recall collapses on the smaller Nigerian corpus.

7.5 Subgraph builder

After fetch, _build_graph_data constructs a node/edge JSON payload (user, item with isTarget, review, category) that is forwarded as a single graph_data event for live NVL rendering. The same payload is the empirical artifact the paper can publish per example.

8. ICL Prompt Composition

Implemented in inference/prompt_builder.py. Five logical blocks fold into two physical messages (system_instruction and contents) for Gemini:

BlockSourceWhat it contributes
A — Shopper profileSQLite personasRating tendency label (tough critic / slightly harsh / balanced / generous), σ, vocab-richness label, emotion label, Pidgin label (NG only), target word-count derived from the user's own historical mean.
B — Style exemplarsNeo4j QUERY_A_*K=3 of the user's own past reviews (text, rating, item name, months-ago) — the strongest persona-fidelity signal.
C — Content groundingNeo4j QUERY_B / Cypher-gen / vectorN=5 reviews from other users about the target item (or semantically near items), each flagged with locale (🇳🇬 for NG) and the retrieval score.
D — Item metadataNeo4j QUERY_ITEM_META (or backfilled from C)Brand, title, category, ₦price, item-average rating across n reviews.
E — Cultural voice overlay (NG only)Static + persona flagsPidgin instruction tier (frequent / occasional / none), value-for-money cue when price_sensitivity > 0.3, authenticity cue when authenticity_concern > 0.3, plus standing notes on delivery / reseller / availability framing.

8.1 Signal derivation

derive_signals(persona, own, others, item_meta) turns raw statistics into human-readable labels that the LLM follows reliably. Examples:

rating_mean < 3.3   → "tough critic"
rating_mean < 3.8   → "slightly harsh"
rating_mean < 4.3   → "balanced"
else                → "generous"

vocab_richness > 0.7 → "rich and varied"
                > 0.4 → "moderate"
                else  → "simple and direct"

pidgin_freq (NG only)  > 0.05 → "frequent"
                        > 0.01 → "occasional"
                        else   → "none"

avg_own_words = clamp(mean(historical word_counts), 5, 150)  # target length

8.2 Rating call (separate)

After the streamed review text completes, a second call (call_rating) sends the generated review plus the user's rating_mean / category_mean / tendency and asks for a single integer 1–5, validated by the ReviewRating Pydantic schema and clamped server-side. If the model returns None, the system falls back to round(clamp(category_mean ?? rating_mean ?? 3.5, 1, 5)), guaranteeing a numeric output.

9. LLM Layer

9.1 Provider abstraction (inference/llm_client.py)

Three public entry points — call_review_stream, call_rating, call_generate_cypher — each dispatch on LLM_PROVIDER ∈ {gemini, groq} to a backend pair. Both backends are coerced into identical Pydantic-validated outputs:

class RetrievalQuery(BaseModel): cypher: str          # MATCH/CALL/RETURN only
class ReviewRating (BaseModel): rating: int           # 1–5

9.2 Gemini backend

  • Streaming: client.aio.models.generate_content_stream(model, contents, config=GenerateContentConfig(system_instruction=…)) yields chunk.text tokens.
  • Structured: generate_content(config=GenerateContentConfig(response_mime_type="application/json", response_schema=ReviewRating)) returns response.parsed already-validated.

9.3 Groq backend

  • OpenAI-compatible /chat/completions over httpx.AsyncClient; SSE data: lines decoded to delta.content tokens.
  • Structured outputs forced via response_format: {type:"json_object"} plus an injected JSON-schema system message; parsed with schema.model_validate_json.

Why the details panel is an overlay, not a flex sibling

NVL's ClickInteraction distinguishes a click from a drag by mouse movement between mousedown and mouseup. When the panel was a flex sibling animating width: 0 → 260, the canvas reflowed mid-click, the hit-test coords shifted, and NVL silently dropped the event as a drag. Anchoring the panel as position: absolute keeps the canvas geometry stable across the open/close animation.

12. Key Architectural Decisions

Gemini 2.5 Flash + native structured outputs

Flash's latency budget suits the multi-call pattern (Cypher gen, review stream, rating) and the google-genai SDK's response_mime_type=application/json + Pydantic response_schema eliminates regex JSON-scraping and removes the finish_reason=2 truncation failure mode we saw with prompt-only JSON requests.

Separate review-text vs rating calls

A single call producing both prose and an integer star rating gives inconsistent calibration (text/rating contradiction in roughly a quarter of generations in informal tests). Splitting them lets the rating call attend to the completed review and explicitly reference rating_mean / category_mean / tendency, producing scores aligned to the persona's historical bias.

Schema-aware Cypher generation + fallback chain

Letting the LLM choose between title-CONTAINS, locale filtering, and vector search per request is more flexible than a fixed template. Pairing it with a deterministic QUERY_B → QUERY_VECTOR fallback bounds the failure mode — bad/empty Cypher never produces an empty prompt context.

SQLite for persona stats, Neo4j for traversal

Persona lookups are point-reads by user_id — sub-millisecond on SQLite, zero ops cost, ships as a single file with the repo. Graph traversal (locale-weighted scoring, category hops, vector search) requires Cypher's expressiveness and a native vector index — neither replicable cheaply on SQLite.

WebSocket over SSE

The graph_data payload is a large structured object (nodes + edges); SSE's text-only framing would force JSON escape-encoding. WebSocket also keeps a single bidirectional channel open for future stop / regenerate signals.

Lazy client-only NVL mount

@neo4j-nvl/base touches document at module-eval, so any SSR or pre-render path crashes. KnowledgeGraph.tsx guards with a mounted state set in useEffect and imports GraphCanvas via React.lazy; the NVL bundle never reaches the SSR worker.

13. Limitations & Future Work

  • Cold persona — users not present in SQLite return an error event. No zero-shot fallback yet (could be a "synthetic persona" derived from declared demographics).
  • Stylometry granularity — current features are surface-level (counts and ratios). Adding syntactic complexity (dependency-tree depth) and topic distributions per user would tighten persona fidelity.
  • Cultural overlay scope — Block E is Nigerian-specific. A locale registry keyed on persona.locale would let the system generalise to other markets.
  • Aspect graph — the pipeline ingests review text but does not yet extract aspects (ABSA). Adding (Review)-[:HAS_ASPECT]→(Aspect) would let retrieval target aspects (battery, sizing, delivery) rather than whole-review similarity.
  • Eval harness — currently informal; a held-out user / item split with rating MAE and a stylometric distance metric (cosine on the stylometry vector) would quantify persona fidelity for the paper.
