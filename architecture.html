4. Schema-Aware Retrieval

Step 1 — Gemini generates the Cypher query

The full DB schema is injected into the prompt. Gemini selects the best query pattern based on the product context and target locale, returning a structured RetrievalQuery {cypher: "..."} object via response_mime_type: "application/json". No regex parsing required.

  • Schema includes node labels, properties, relationships, and vector index name
  • Gemini can choose locale filtering, title CONTAINS matching, or vector search as appropriate
  • Output is a plain Cypher string — no markdown fences (structured output guarantee)

Step 2 — Execute with fallback chain

The generated query runs with params $user_locale and $item_vec. If it returns no rows or throws, the pipeline falls through:

  • Fallback A — QUERY_B: locale-weighted Cypher using known item_id (N=5)
  • Fallback B — vector index: embed item_name + description via all-MiniLM-L6-v2, cosine threshold > 0.72

Branch label in UI

  • "ppr" → badge shows PPR Retrieval
  • "vector" → badge shows Semantic Search

9. Key Architectural Decisions

Gemini 2.5 Flash + google-genai SDK — not GPT-4 or Claude

Flash's speed-to-quality ratio suits the four-call pattern (NL extract, Cypher gen, review text, rating integer) at low latency. The new google-genai SDK enables enforced structured outputs via response_mime_type: "application/json" + Pydantic schema — eliminating regex parsing and finish_reason=2 crashes. The model's instruction-following is strong enough for the 5-block ICL context.

Separate rating call (Call 2)

Asking the LLM to produce both review text and a rating in one pass produces inconsistent star calibration — the text often contradicts the number. Separating the calls lets Call 2 see the full review and explicitly reference the user's historical mean, producing ratings that track the persona's calibration curve.

WebSocket over SSE

The graph_data event is a large structured JSON payload (nodes + edges). SSE is text-only and would require JSON escaping overhead. WebSocket supports binary framing, bidirectional flow (useful for future stop signals), and keeps a single connection open for all event types without multiplexing.

SQLite for persona stats, Neo4j for graph traversal

Stylometry and rating stats are point-lookups by user_id — perfect for SQLite at sub-millisecond latency. Graph traversal (PPR, locale-weighted scoring, category hops) requires the query language expressiveness of Cypher, which SQLite cannot replicate efficiently at this scale.
