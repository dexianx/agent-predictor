1. Abstract & Design Goals

Kora is a user-modelling system that, given a known shopper U, a product name P, and a price $, generates a free-form review and a 1–5 star rating that mimic U's historical voice, rating calibration, and cultural register (with a Nigerian-locale specialisation). The system combines (i) an offline persona-construction pipeline ingesting Amazon US reviews across three categories, Nigerian e-commerce (Jumia/Konga), and Google Maps NG place reviews; (ii) a Neo4j knowledge graph with a 384-dim vector index over review embeddings; (iii) a SQLite persona store of 17 stylometric and rating-bias signals for ~25k users; and (iv) an online inference path that performs category-scoped Cypher retrieval (with LLM Cypher and vector fallbacks) and a two-call LLM in-context-learning generation, streamed to the client via WebSocket. Retrieval is anchored on product category and brand, not item ID — enabling accurate behavioural prediction for products not yet in the knowledge graph.

Goals: (1) persona fidelity — output reads like the specific user, not a generic reviewer; (2) locale grounding — Nigerian shoppers' Pidgin/price/authenticity register is preserved; (3) retrieval transparency — every generation is traceable to the graph subgraph that produced it; (4) price-aware generation — submitted price is authoritative and overrides all graph-stored values; (5) low-latency streaming — first token under one second on warm models.

LLM provider swap — how it works

All three call sites (call_generate_cypher, call_review_stream, call_rating) dispatch on a single LLM_PROVIDER environment variable at call time. Both providers implement the same Pydantic output contracts — RetrievalQuery{cypher} and ReviewRating{rating} — so switching providers requires no code changes, only an env var. 4.1 Source ingestion (pipeline/sources.py)

  • Amazon (McAuley-Lab/Amazon-Reviews-2023) — US-locale corpus, 3 categories: Home_and_Kitchen, Electronics, Cell_Phones_and_Accessories. Includes item metadata: features, description, priceUsd, parentAsin, boughtTogether.
  • Nigerian e-commerce (combined_ecommerce_source) — Jumia/Konga combined product reviews keyed on asin, joined with load_combined_meta for item metadata including priceNgn. Locale hard-coded to "NG".
  • Google Maps NG (google_maps_source) — Nigerian-place reviews from nigeria_reviews.csv, joined with nigeria_places.csv by place_id. Platform: "google_maps_ng". No price data.

4.2 Persona-friendly sampling

Naive uniform sampling collapses persona signal because most users contribute a single review. persona_friendly_sample stratifies by user_id, preferring users with ≥ MIN_WORDS_FOR_STYLOMETRY=5-word reviews and ≥ 2 historical reviews. Target split: 2500 Amazon + 1500 NG e-commerce + 1000 Google Maps = 5000 total records.

4.3 Stylometry enrichment (pipeline/enrichment.py)

17 signals computed per review then averaged per user into the persona store:

compute_stylometry(text) → {
  avg_sent_len,        # mean sentence length in words
  vocab_richness,      # type-token ratio (unique / total tokens)
  exclamation_rate,    # exclamation marks / total tokens
  caps_rate,           # ALL-CAPS words / total words
  pidgin_freq,         # share of tokens in PIDGIN_TOKENS lexicon (NG signal)
  emoji_rate,          # emoji chars / total chars
  question_rate,       # question marks / total tokens
  avg_word_len,        # mean characters per token
  uppercase_word_rate, # words starting with capital / total words
  naira_mention,       # bool — contains "₦" or "naira"
  price_sensitivity,   # bool — contains price-comparison language
  authenticity_concern # bool — contains fake/counterfeit/original language
}

PIDGIN_TOKENS = { "na", "sha", "dey", "abeg", "abi", "oga",
                  "wahala", "nawa", "sabi", "chop", "wey",
                  "dem", "una", "comot", "wetin", "sef", "joor" }

Reviews shorter than MIN_WORDS_FOR_STYLOMETRY=5 tokens get an empty stylometry dict and are excluded from per-user aggregation. Boolean flags (price_sensitivity, authenticity_concern) are averaged to produce a per-user rate in [0,1].

4.4 Per-user aggregation

UserAccumulator ingests every enriched record, then flushes to SQLite. Users with fewer than MIN_REVIEWS_FOR_PERSONA=3 reviews are written but flagged is_persona_eligible=0. Two tables:

  • personas — one row per user_id: locale, platform, review_count, rating_mean, rating_std, rating_skew, top_categories (JSON array), plus mean of all 12 stylometry metrics above.
  • category_rating_bias — (user_id, category) → (mean, count); used at inference to predict ratings within the target category rather than the user's global mean.

A selected boolean flag marks hand-curated "featured" personas shown in the sidebar (1 NG + up to 15 US).

5.1 Property name note

Item properties in the graph use camelCase (priceNgn, priceUsd, avgRating, ratingCount). QUERY_ITEM_META aliases these to snake_case for Python consumption. This distinction matters when writing raw Cypher in LLM-generated queries.

5.3 Featured persona selection

load_featured_personas always returns exactly 1 NG persona (highest review_count with selected=1) + up to 15 US personas (selected pool first, then unselected pool as top-up). This guarantees the sidebar always includes a Nigerian user for demo purposes.

7. Retrieval Subsystem

The retrieval goal is behavioural context prediction, not product lookup. The system gathers evidence of how users write about products in a given category so the generative model can predict the most likely review. Three branch labels are recorded on every graph_data event and the final payload for auditable provenance.

BranchTriggerOwn reviews (style anchors)Others' reviews (content anchors)
categoryCategory resolved from graph metadata (primary path)QUERY_A_SAME_CAT_BY_NAME: user's past reviews filtered by cat.name CONTAINS categoryQUERY_CATEGORY_REVIEWS: locale+recency scored, scoped to category — no item_id needed
queryNo category resolved; raw_message or item_name presentQUERY_OWN_RECENT (any category fallback)LLM-generated Cypher (schema + item_name + brand + category) → QUERY_VECTOR

7.1 Style anchors — user's own reviews (Session 1)

QUERY_A_SAME_CAT_BY_NAME  -- primary path when category known
  MATCH (u:User)-[:WROTE]->(r:Review)-[:ABOUT]->(i:Item)-[:IN_CATEGORY]->(cat:Category)
  WHERE toLower(cat.name) CONTAINS toLower($category)
  ORDER BY age ASC  LIMIT K=3
  -- surfaces user's writing style + rating tendency in this product space

QUERY_OWN_RECENT  -- fallback when no category resolved: any category, most recent K reviews

Category-scoped own reviews are more useful than "any recent reviews" because they capture domain-specific vocabulary, rating calibration, and price-sensitivity patterns. A user who rates Electronics harshly but Fashion generously has different stylometric signals per category.

7.2 Content anchors — others' reviews (Session 2)

QUERY_CATEGORY_REVIEWS  (Tier 1 — primary, deterministic):
  MATCH (i:Item)-[:IN_CATEGORY]->(cat:Category)
  WHERE cat.name CONTAINS $category OR i.category CONTAINS $category
  MATCH (r:Review)-[:ABOUT]->(i), (other:User)-[:WROTE]->(r)
  WHERE other.id <> $user_id
  score = locale_w × 0.6 + recency_decay × 0.4 + brand_w
    locale_w = 1.0 if r.locale = user_locale else 0.3
    recency_decay = 1÷(1+age÷12)
    brand_w = 0.10 if $brand <> "" AND toLower(i.brand) CONTAINS toLower($brand) else 0.0
  ORDER BY score DESC  LIMIT N=5
  -- no item_id needed; uses indexed item_category field for performance

QUERY_VECTOR  (Tier 3 — last resort):
  embed_text = item_name + brand + category + features_snippet + details_snippet
               ← rich fields tighten KNN neighborhood;
                 features/details add material, compatibility, certification signals
  CALL db.index.vector.queryNodes('review_embedding', 15, $item_vec)
  WHERE similarity > 0.72
  ORDER BY locale_match DESC, similarity DESC  LIMIT N=5

7.3 LLM Cypher generation (Tier 2 fallback)

generate_retrieval_query(user_query, user_locale, item_name, item_brand, item_category) now receives structured product fields as separate prompt variables (not a freeform blob). The LLM injects the full graph schema plus explicit brand and category anchors to write targeted Cypher. Fires only when QUERY_CATEGORY_REVIEWS returns 0 rows (category not in graph or too narrow). Falls through to QUERY_VECTOR on Cypher error or empty result.

The generation prompt enforces four neutrality rules to avoid biased ICL examples:

RuleMechanism
Rating mixTarget distribution across 8 rows: 2 positive (≥4★), 1 negative (≤2★), 1 neutral (3★ same locale), 4 best-match any rating. Use UNION or multiple MATCH branches with explicit WHERE r.rating conditions.
ScopePrioritise category + brand. Only expand to adjacent subCategories if <4 results. Block generic keyword matches (e.g. "battery", "camera") that cross product categories.
Anti user-biasCap single-user dominance at 2 reviews: WITH u, collect(r)[..2] AS capped UNWIND capped AS r
Multi-item spreadDistribute across at least 2 distinct items — model receives signal from more than one product's review pool.

7.4 Title resolution (QUERY_RESOLVE_BY_TITLE)

MATCH (i:Item)
WHERE toLower(i.title) CONTAINS toLower($keyword)
RETURN i.id AS id, i.title AS title
ORDER BY size(i.title) ASC   -- shortest match first
LIMIT 1

Title resolution is used only to extract category and brand from the graph for use as retrieval anchors. It no longer promotes the request to a PPR/item-specific retrieval branch. Whether or not title resolves, the primary retrieval path is always category-scoped.

7.5 Graph data builder

After fetch, _build_graph_data constructs a node/edge JSON payload for live NVL rendering. Node types: user, item (with isTarget=True on the requested item), review (with text snippet, rating, score, age), category. Edge labels: WROTE, ABOUT, IN_CATEGORY. The payload is forwarded as a graph_data WebSocket event and is the empirical artifact the paper can publish per example.

NVL's ClickInteraction distinguishes a click from a drag by mouse movement between mousedown and mouseup. When the panel was a flex sibling animating width: 0 → 260, the canvas reflowed mid-click, hit-test coords shifted, and NVL silently dropped the event as a drag. Anchoring the panel as position: absolute keeps the canvas geometry stable across the open/close animation.

12. Key Architectural Decisions

Request fields are authoritative — override runs last

Retrieval backfill code can overwrite item_meta["title"] with a graph-matched product name (e.g. resolving "MX Keys S" to "K350"). The authoritative override block runs unconditionally after all retrieval and backfill, writing request.item_name and request.price_ngn into item_meta. This guarantees the caller's explicitly submitted data always reaches the LLM prompt.

Separate review-text vs rating calls

A single call producing both prose and an integer star rating gives inconsistent calibration (text/rating contradiction in roughly a quarter of informal test generations). Splitting them lets the rating call attend to the completed review and explicitly reference rating_mean / category_mean / tendency, producing scores aligned to the persona's historical bias.

Gemini 2.5 Flash + native structured outputs

Flash's latency budget suits the multi-call pattern. The google-genai SDK's response_mime_type=application/json + Pydantic response_schema eliminates regex JSON-scraping and the finish_reason=2 truncation failure mode seen with prompt-only JSON requests.

Four-rule neutrality in LLM Cypher generation

Unconstrained Cypher generation tends to fetch positive reviews (because they're more common and rank higher in cosine similarity). The rating-mix rule (2 pos / 1 neg / 1 neutral / 4 best-match), anti-user-bias cap, scope guard, and multi-item spread are injected into the generation prompt to produce balanced ICL content anchors that don't inflate the LLM's sentiment baseline.

SQLite for persona stats, Neo4j for traversal

Persona lookups are point-reads by user_id — sub-millisecond on SQLite, zero ops cost, ships as a single file. Graph traversal (locale-weighted scoring, category hops, vector search, title CONTAINS) requires Cypher's expressiveness and a native vector index — neither replicable cheaply on SQLite.

Two independent sessions for own + others retrieval

The Neo4j async driver socket is not safe for concurrent reads on a single session. fetch_retrieval opens two independent async sessions (s1 for own reviews, s2 for others) sequentially, avoiding driver-level race conditions while keeping both queries logically parallel in the code.

WebSocket over SSE

The graph_data payload is a large structured object (nodes + edges). SSE's text-only framing would force JSON escape-encoding. WebSocket also keeps a single bidirectional channel open for future stop / regenerate signals.

Lazy client-only NVL mount

@neo4j-nvl/base touches document at module-eval, so any SSR or pre-render path crashes. KnowledgeGraph.tsx guards with a mounted state set in useEffect and imports GraphCanvas via React.lazy; the NVL bundle never reaches the SSR worker.

13. Limitations & Future Work

  • Cold persona — users absent from SQLite return an error event. No zero-shot fallback yet (could be a "synthetic persona" derived from declared demographics or item category alone).
  • Category resolution fragility — QUERY_RESOLVE_BY_TITLE uses a CONTAINS match to get the category/brand metadata. A product not in the graph at all (no CONTAINS match) falls to LLM Cypher or vector, which may miss niche product spaces. Category normalisation (e.g. "earbuds" → "Headphones") would improve recall.
  • US price field gap — the form always submits into price_ngn; price_usd is populated only from graph-stored Amazon metadata. The fallback price_usd OR price_ngn in build_user_prompt works correctly but mixes currency semantics.
  • Stylometry granularity — current features are surface-level (counts and ratios). Adding syntactic complexity (dependency-tree depth) and per-category topic distributions would tighten persona fidelity.
  • Cultural overlay scope — Block E is Nigerian-specific. A locale registry keyed on persona.locale would generalise to other markets (GH, KE, ZA).
  • Aspect graph — the pipeline ingests review text but does not extract aspects (ABSA). Adding (Review)-[:HAS_ASPECT]→(Aspect) would let retrieval target specific dimensions (battery, sizing, delivery) rather than whole-review similarity.
  • Eval harness — implemented; see §14 Evaluation Layer.
  • LLM price grounding — even with Price: $2 explicitly in the prompt, models with strong product-price priors from training data may not surface the price in review text unless the system prompt also contains an explicit "comment on value for money" instruction (gated on price_sensitivity > 0.1).

14. Evaluation Layer

The evaluator is a pure downstream consumer: it hands a request to the existing workflow, receives the workflow's output plus the references the workflow used, and scores. It must not call Neo4j, must not compute item embeddings, and must not import fetch_retrieval. The system owns the workflow; the evaluator owns scoring.

Scoring formula: Score = 1 − (0.25·EmotionalToneError + 0.25·SentimentAttitudeError + 0.5·TopicRelevanceError)

Current Failure Pattern

  • Cold-start / unseen-product gap. The 50-case masked eval (target item label hidden in Neo4j) shows RMSE 0.9899 vs 0.7746 for known items — a +0.22 gap. All 50 masked cases fall into the item_vector branch. The system relies heavily on exact-item community reviews; when those are unavailable, item-vector neighbors carry the full load. Richer product input (brand/category/features/details) closes this gap by 0.040 RMSE but does not eliminate it. The fix is richer cold-product reasoning from metadata + rating-bucket-diverse item-vector retrieval.
  • Retrieval bias → catastrophic low-star misses. When a product's DB representation is skewed positive (high-rated reviews are more recent or same-locale), QUERY_B returns all-positive evidence. The model rationally generates a positive review with no basis for a negative rating. Pass 11 addresses this with a negative-evidence supplement query.
  • Hallucinated caveats on true 5-star items. The model occasionally adds mild qualifiers ("slightly smaller", "feels a bit cheap") on genuinely positive items, causing the rating model to predict 4 instead of 5. The anti-caveat approach (Pass 9, 10) was too risky because the same suppression harms true 4-star items. A safer approach would require the model to cite specific retrieved evidence for any caveat.
  • Short Nigerian reviews achieve near-zero ROUGE-L. A terse heldout like "Stopped working on the first day" generates ROUGE-L ≈ 0 even when the generated text is semantically aligned. This is a metric artifact, not a generation failure.
  • Post-Pass 9/10 lesson: prompt rules conditioned on retrieval signal quality are unsafe when the retrieval itself is biased. Fix the retrieval gap first, then re-evaluate whether prompt rules are still needed.
